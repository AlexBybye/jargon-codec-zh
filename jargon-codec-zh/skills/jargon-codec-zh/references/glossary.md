## 协作与交付

| 黑话 | 普通话含义与边界 |
|---|---|
| 对齐／拉齐 | 同步目标、信息、方案、口径或预期；不自动表示已经达成一致。 |
| 拉通 | 协调多个团队、环节或系统共同推进。 |
| 打通 | 消除流程、数据或系统间的阻碍，使其连贯运行。 |
| 串联 | 按顺序连接人员、步骤、能力或信息。 |
| 透传 | 信息或数据未经业务加工地原样传递。 |
| 抓手 | 推动目标的具体切入点、措施或载体。 |
| 闭环 | 从输入、执行、结果到反馈或验收形成完整链条，不只是“做完”。 |
| 落地 | 把想法或方案变成已执行、可验证的结果。 |
| 收口／收敛 | 缩小范围、减少分歧并形成结论。 |
| 发散 | 暂时扩大思路和候选方案范围。 |
| 复盘 | 按目标、过程、结果和原因回顾工作。 |
| 沉淀 | 把经验、数据或能力整理成文档、流程、规则、组件等可复用资产。 |
| 拆解 | 把目标分为任务、指标、阶段或责任人。 |
| 梳理 | 把零散信息、关系或步骤整理清楚。 |
| 颗粒度 | 信息、需求、任务或数据的细致程度。 |
| 对标 | 选择参照对象并比较差距，不等于照抄。 |
| 跟进 | 持续关注并推进，可能兼有催办含义。 |
| 倒逼 | 用期限、结果或约束反向推动前置行动。 |
| 赋能 | 提供能力、工具、权限或资源；普通话应说明谁给谁什么。 |
| 支撑 | 为业务或上层能力提供基础支持。 |
| 加持 | 增加资源、优势或背书，宣传色彩较强。 |
| 反哺 | 下游成果、数据或收益反向支持上游。 |
| 协同／联动 | 多方共同配合／一方变化触发另一方响应。 |
| 共建／共创 | 共同建设／共同参与设计创造，不能凭词推定投入深度。 |
| 方法论 | 较系统、可复用的做事方法；一次经验不必拔高。 |
| 组合拳 | 多项相互配合的措施；列不出措施时通常只是修辞。 |
| owner／主 R／DRI | 主要负责人，叫法依组织而异。 |
| 单线程 owner | 一名主要负责人统一推动，不表示独自完成全部工作。 |
| 排期 | 工作计划及预计完成时间。 |
| milestone／checkpoint | 关键阶段节点／中间检查点。 |
| sign-off | 相关负责人正式确认或批准。 |
| SOP | 标准操作流程。 |
| SLA／SLO／SLI | 服务承诺／服务目标／实际衡量指标，三者不要混用。 |
| all in | 集中投入主要资源，不能据此虚构投入规模。 |

## 产品运营与增长

| 黑话 | 普通话含义与边界 |
|---|---|
| 痛点／痒点／爽点 | 急需解决的问题／潜在吸引点／即时满足点。 |
| 场景／场域 | 用户在特定环境中完成某类任务的情境；“场域”包装感更强。 |
| 用户画像 | 对目标用户特征、需求和行为的结构化描述。 |
| 用户旅程 | 用户从进入到完成目标的完整路径。 |
| 用户心智 | 用户对品牌、品类或使用场景形成的认知关联。 |
| 触点／触达 | 用户接触产品的位置／把信息送达用户；触达不等于已阅读或转化。 |
| 千人千面 | 根据不同用户提供个性化内容或体验。 |
| 冷启动 | 在缺少用户、数据或供给的初始阶段启动。 |
| 种子用户 | 最早参与验证并提供反馈的一批用户。 |
| MVP | 用最少必要能力验证关键假设，不等于随意删功能。 |
| POC | 小范围验证方案是否可行、是否有价值。 |
| PMF | 产品价值与市场需求达到较好匹配，不是永久认证。 |
| JTBD | 从用户要完成的任务理解需求。 |
| 拉新／激活／促活 | 获得新用户／让新用户完成关键动作／提高现有用户活跃。 |
| 留存／召回 | 用户持续使用／让流失用户回来；检索语境的召回指找回相关内容。 |
| 转化／变现 | 用户进入目标状态／把产品或流量转成收入。 |
| 转化漏斗／AARRR | 连续环节的转化模型／获客、激活、留存、收入、推荐框架。 |
| 公域／私域 | 平台公开流量／企业可持续直接触达的用户关系渠道。 |
| 裂变 | 通过分享、邀请等形成扩散增长。 |
| 流量池／入口／导流 | 可持续触达的流量／用户进入渠道／把用户引到另一渠道。 |
| 投放／买量／自然量 | 付费获取曝光或访问／付费获客／非直接付费获得的流量。 |
| 全域经营 | 综合多个平台、渠道和用户关系经营，口径依平台。 |
| 精细化运营／用户分层 | 按用户特征和行为采取差异化策略。 |
| 北极星指标 | 代表产品核心价值交付的关键指标，可随阶段变化。 |
| 飞轮／数据飞轮 | 一环结果持续帮助下一环变好，必须有真实反馈链路。 |
| 护城河／壁垒 | 难以复制的优势，需要落到数据、技术、渠道、品牌或流程。 |
| 第二曲线／赛道 | 新增长来源／业务竞争领域。 |
| 红海／蓝海 | 竞争激烈的成熟市场／竞争较少的新市场。 |
| 破圈／出圈 | 从原有用户群扩展到更广人群。 |
| 下沉市场 | 相对低线城市或未充分覆盖的人群市场。 |
| 品效合一 | 品牌建设与短期转化同时有效，不能凭词推定已经实现。 |
| 矩阵／打法／玩法 | 多账号、多产品或多渠道组合／推进目标的策略和执行方式。 |
| 钩子 | 吸引注意或促使下一步行动的内容或机制。 |

## 职场组织与招聘

| 黑话 | 普通话含义与边界 |
|---|---|
| PM／PD／RD／QA | 产品或项目经理／含义因公司而异／研发职能／质量保证职能。 |
| BP／HC | 业务伙伴类岗位／招聘名额或编制。 |
| Base | 可能指工作地点，也可能指基本薪资。 |
| Package／RSU／期权 | 总薪酬组合／限制性股票单位／按约定条件购买股份的权利。 |
| 背调／offer | 招聘背景调查／录用通知或工作邀约。 |
| OD／外包 | 外部雇佣或派遣形式，具体劳动关系看合同。 |
| P0／P1／P2 | 优先级或故障等级，数字方向和含义依组织规则。 |
| 活水 | 一些公司对内部转岗机制的称呼。 |
| 优化 | 可能指改善产品、性能或流程，也可能委婉指人员调整。 |
| 毕业 | 可能指正常毕业，也可能委婉指离职或裁员。 |
| 向社会输送人才 | 裁员调侃，不当成正式事实表述。 |
| 降本增效／提质增效 | 降低成本并提高效率／提高质量和效率。 |
| 扁平化 | 减少管理层级或沟通距离，不等于没有管理。 |
| 组织提效 | 调整流程、角色或资源以提高效率，需说明具体动作。 |
| 文化 fit／高潜 | 与组织工作方式匹配／被认为具有较高成长潜力。 |
| 画饼／背锅 | 用未来收益激励当下投入／为问题承担责任，常带讽刺意味。 |
| 摸鱼／划水／内卷 | 降低工作投入／低投入应付／收益未增长时持续加码竞争。 |
| 体感／水位 | 主观感受／进度、能力、指标或资源所处水平。 |

## 数据商业与实验

| 黑话 | 普通话含义与边界 |
|---|---|
| DAU／WAU／MAU | 日／周／月活跃用户；活跃定义需说明。 |
| PV／UV | 页面访问次数／独立访问者数量。 |
| CTR／CVR | 点击率／转化率，分母和转化目标必须明确。 |
| CAC／LTV | 获得客户的成本／客户生命周期价值，计算口径依业务。 |
| ARPU／ARPPU | 每用户／每付费用户平均收入。 |
| ROI／ROAS | 投资回报／广告收入相对广告支出的回报。 |
| GMV | 商品交易总额；是否含未付款、取消或退款依平台口径。 |
| ARR／MRR／NRR | 年／月经常性收入／老客户净收入留存率。 |
| 同比／环比 | 与去年同期／上一相邻周期比较。 |
| 大盘／下钻 | 整体业务数据／从汇总指标查看更细维度。 |
| 归因分析 | 分析结果可能由哪些因素贡献；相关性不等于因果。 |
| 指标口径／阈值／基线 | 指标定义与范围／触发动作的临界值／比较参照。 |
| Benchmark／Eval | 通用基准／目标场景中的系统评测。 |
| A/B 测试 | 随机分组比较版本，还需考虑样本、污染和统计方法。 |
| Cohort／Holdout | 按共同起点分组观察／保留不参与当前调整的样本或用户。 |
| 护栏指标／增量 | 防止伤害其他结果的限制指标／相对未采取动作真正增加的结果。 |
| 单位经济 | 单个客户、订单或成功任务的收入、成本和利润关系。 |
| TAM／SAM／SOM | 总市场／可服务市场／当前可获得市场。 |
| GTM／PLG | 进入市场的整体策略／主要由产品体验推动增长。 |
| Land and Expand | 先在客户内部小范围使用，再扩到更多团队或场景。 |

## 研发架构与稳定性

| 黑话 | 普通话含义与边界 |
|---|---|
| 技术栈／架构 | 所用语言框架工具的组合／系统组件及其关系。 |
| 中台 | 为多个业务复用的共享能力，不是泛指后台。 |
| 微服务／单体 | 独立部署的服务组合／主要功能整体构建部署。 |
| 解耦／耦合 | 降低／描述模块间依赖程度。 |
| 抽象／封装／复用 | 提取共同规则／隐藏内部实现／重复使用已有能力。 |
| 组件化／模块化 | 把系统拆成职责清楚、可组合的单元。 |
| 上游／下游／链路 | 前一环／后一环／请求、数据或业务动作经过的环节。 |
| 端到端 | 覆盖从输入到最终结果的完整过程，原文不完整时不要滥用。 |
| 灰度／全量／回滚 | 向部分用户发布／向全部目标用户开放／恢复到先前状态。 |
| 降级／兜底／fallback | 简化非核心能力／最后保障／备用处理。 |
| 限流／熔断 | 限制请求量／持续故障时暂时停止调用。 |
| 容错／容灾 | 局部错误时继续工作／重大故障下恢复服务。 |
| 可观测性／Tracing | 用日志指标追踪理解状态／记录请求跨组件路径。 |
| On-call／Incident／RCA | 值班响应／线上故障事件／根因分析。 |
| Postmortem／Runbook | 故障复盘／运维或故障处理手册。 |
| Error Budget | 在可靠性目标范围内可承受的失败量。 |
| 技术债 | 短期权宜方案造成的后续维护成本。 |
| QPS／TPS | 每秒查询量／每秒事务量，具体类型由系统定义。 |
| P99／TP99／N 个 9 | 第 99 百分位延迟／可用性百分比简写。 |
| 幂等／重试 | 重复执行不增加副作用／失败后再次执行。 |
| Feature Flag／UAT／CI/CD | 功能开关／用户验收测试／持续集成与交付部署。 |

## AI 模型数据与推理

| 黑话 | 普通话含义与边界 |
|---|---|
| AIGC／GenAI／LLM／VLM／SLM | 生成式 AI／大语言模型／视觉语言模型／小型语言模型。 |
| 基座模型／前沿模型 | 可继续适配多任务的通用模型／当前能力领先的一类模型。 |
| 开放权重 | 可获得模型权重，不等于代码、数据和许可证全部开源。 |
| MaaS | 通过托管服务调用模型能力。 |
| 预训练／后训练／微调／SFT | 基础训练／之后的行为调整／特定数据适配／监督微调。 |
| LoRA／QLoRA／PEFT | 用较少可训练参数适配模型的一类高效微调方法。 |
| RLHF／DPO／RLVR／GRPO | 不同偏好或强化学习优化方法，不互称简单替代品。 |
| 推理模型／CoT | 针对多步问题优化的模型／分步推理提示或可见推理文本。 |
| Reasoning Effort／Inference-time Scaling | 调整推理投入／回答阶段增加计算或搜索。 |
| Token | 分词器定义的模型处理单位，不是固定“语义单位”。 |
| 上下文窗口／长上下文 | 一次请求可处理的范围／处理较长输入的能力；装得下不等于用得好。 |
| Context Engineering | 组织指令、示例、资料、工具和历史信息。 |
| Prompt Engineering／System Prompt／Few-shot | 提示设计／高优先级行为指令／提供少量示例。 |
| Temperature／Top-P／Top-K | 控制采样分布的参数，范围与效果依实现。 |
| Structured Output | 按 JSON Schema 等结构返回结果。 |
| 多模态 | 处理多种输入或输出模态，必须区分理解与生成能力。 |
| 蒸馏／量化／MoE | 教师模型帮助训练小模型／降低数值精度／稀疏专家架构。 |
| 合成数据／标注／清洗／去重 | 生成数据／添加标签／修正低质量内容／删除重复。 |
| PII | 可识别具体个人的信息，处理要求依用途、授权和法规。 |

## AI 产品 Agent 检索与评测

| 黑话 | 普通话含义与边界 |
|---|---|
| RAG | 先检索资料，再让模型依据资料回答；不保证一定正确。 |
| Embedding／向量数据库／Chunking | 向量表示／向量存储检索／把长资料分段。 |
| Hybrid Search／Rerank／Query Rewrite | 关键词加向量检索／重排结果／改写查询。 |
| GraphRAG | 利用实体关系或图结构辅助检索和组织信息。 |
| Grounding／Citation／幻觉 | 基于可验证资料／给出来源／缺少依据或错误的生成内容。 |
| Agent | 能分步骤并借助工具完成任务的 AI 应用，不等于完全自主。 |
| Tool／Function Calling | 模型提出工具调用，宿主负责校验、授权和执行。 |
| MCP／A2A | 连接宿主、工具和上下文的协议／Agent 间交互方式。 |
| Agentic Workflow／Orchestration | 含模型决策的工作流／组合模型、工具、数据和步骤。 |
| Agent Harness／Runtime／Subagent／Skill | Agent 运行环境／派生子任务 Agent／领域能力包。 |
| Memory | 跨轮或跨会话保留信息，与上下文窗口、KV Cache 不同。 |
| Sandbox／Permission／Approval | 执行隔离／最小权限范围／高风险动作前人工确认。 |
| HITL／Copilot／Autopilot | 人工确认进入流程／人机协作／授权范围内更多自动执行。 |
| Guardrail／Fallback／Degradation | 检查限制／备用方案／降低非核心能力。 |
| Prompt Injection／Jailbreak／Red Team | 外部内容劫持指令／绕过限制／主动模拟攻击。 |
| Eval／Golden Set／Human Eval／LLM-as-judge | 系统评测／稳定回归集／人工评价／模型评价模型。 |
| Offline／Online Eval | 离线案例评测／真实使用环境中的在线评测。 |
| Faithfulness／Retrieval Eval | 回答是否忠于证据／检索是否找到相关完整资料。 |
| 任务完成率／Aha Moment／TTV | 任务真正完成比例／首次感到有用／获得价值所需时间。 |
| TTFT／TPOT／Latency／Throughput | 首个输出时间／后续 Token 时间／单次耗时／单位时间处理能力。 |
| Streaming | 生成时逐步返回，改善等待体验但不保证总耗时更短。 |
| KV Cache／Prompt Cache／Speculative Decoding | 生成状态缓存／前缀缓存／小模型猜测后由大模型验证。 |
| Model Router／Serving／LLMOps | 模型分流／部署推理服务／模型应用工程化管理。 |
| AI Native／Vibe Coding／Generative UI | 核心流程围绕 AI 重设／自然语言驱动编码／动态生成界面。 |

## 两档表达规律

### 黑话转普通话

补全“谁 + 做什么 + 对谁或什么 + 何时完成 + 如何验收”。例如：

- “围绕增长抓手，拉通链路，沉淀方法论” → “明确一项增长措施，协调相关环节实施，并把验证有效的做法整理成可复用流程。”
- “打通 Agentic Workflow” → “把模型、工具和人工确认步骤串起来，让任务按既定流程执行。”
